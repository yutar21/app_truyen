## 感情线（本书档位：Nồng thắm (Nhân vật trưởng thành)）

- 怎么写：感情戏是本书主线之一，篇幅和分量要给足。**标准是「色而不淫」——不是回避，是写而不露**：
  · **仅限成年角色**。角色未成年时一律按「暧昧」档写，成年之后再放开。这条没有例外。
  · **该发生的要发生**：接吻、拥抱、共处一夜都可以写、可以点明。恋爱写得不亲不碰，人物是假的，读者也不信。
  · **写感官，不写器官**：呼吸乱了半拍、颈侧的温度、指尖停在纽扣上的那一下犹豫、衣料摩擦的声响、她头发上的皂角味。这些比任何直白描写都更有情欲张力，而且过审。**绝不出现身体部位的名称与动作过程。**
  · **写克制的瞬间**：想碰没碰、碰了又收回、话说到一半被打断。情欲的张力全在"差一点"上，一旦写全了，反而没了。
  · **写事后，不写事中**：真到了那一步，用一个转场（雨声、灯灭、翻倒的搪瓷缸）过去，力气花在次日清晨的一个细节上——谁先醒的、谁没敢看谁、一件被叠好的衣服。事后一句顶事中一千字。
  · **情绪重量优先**：读者该记住的是"他们之间从此不一样了"，不是"发生了什么"。
  · 底线仍在：不写露骨过程、不写生理细节、不用情色化的比喻（把身体比作食物/器物那类）。越线的代价是整本书下架——写到八分收手，是本事，不是怯懦。Tình cảm sâu sắc, văn minh đúng chuẩn.

**感情线红线（任何档位都不放宽，越线整本书会被下架）**：
- **未成年角色（不满 18 岁）一律只到「少年心动」**：距离、觉察、未完成的动作、物件寄情；不写身体、不写亲密行为。这是法律红线，不是平台尺度。
- 任何档位都**不写露骨性行为、生殖器官、性过程**；需要交代时用场景转换或次日的细节带过。
- 不写强迫、交易、以及师生/上下级这类权力不对等关系里的亲密戏。
- 简介与书名同样受此约束：**物化异性的招徕语（「随便挑选」「无数美女」这类）比正文更容易触发审核**，因为它挂在书封页上。

## 章节文件规则

- 扩展名 `.txt`；文件名 = 全局章号 + 唯一章名，如 `001重生.txt`、`206白袖人再递糖签.txt`。
- **章号必须是【全书全局连续编号】**：从 001 起跨卷一直往上数（卷02 接着卷01 末尾的号继续，绝不是每卷都从 001 重新数）。例：卷01 写到 040，则卷02 第一章是 041 而非 001。这样全书章节才能正确排序、续写才接得上。
- 章号至少 3 位零填充（直到 999）。**章名全书唯一，绝不重复**——取名前必须在 `chapter_index.md` 全表检索确认无同名（连意思高度相近的也错开）；这是长书最易犯的错（写到后面忘了前面用过的名），务必每次查重。
- 放入正确的卷目录。内容仅正文，不含任何标题/注释/元信息。

## 写作标准

- 每章结构完整：场景铺垫 → 冲突或发现 → 人物推进 → 钩子或压力点。
- 长线节奏：不抢着在出现的同一章解决张力；重大反转、表白、实力跃迁、反派暴露都要铺垫。
- 用前文连续性锚点：未决之物、证人、欠债、伤势、文书、关系、承诺。
- 线索可用但不过早定论，侦查类剧情用"待查"逻辑。
- 人物靠反复选择成长，而非宣言。

## 节奏与格局（最高优先级，逐章 + 逐卷自检）

写网文不是写档案。读者要的是**人物在推进、格局在变大、隔几章有一次可感的回报**。下面是硬约束：

**1. 每章必须推进“人”与“冲突”，不是“流程”**
- 每章要让一个真实的人物目标、冲突或抉择往前走一步；章末要有让人想看下一章的钩子。
- **严禁把办手续/验册/对账/盘点/办牌证/抄报/登记这类事务流程本身当作章节主线事件**。账册、牌证、公文、清算、卷宗只能作为**背景质感、障碍或筹码**出现，不能占据整章。
- **禁止连续 ≥2 章以行政/事务流程为主要内容**。这类事务要压缩成段落、概述带过，或并入一场更大的冲突里解决。

**2. 格局必须随卷可感地升级**
- 每卷的一个阶段目标，原则上用 **3–8 章**兑现，不得无限拉长成几十章。
- 主角的处境——地点、权力层级、实力、人脉、所辖范围、对手量级——**必须随章节推进明显升级**，不能长期困在同一地点、同一层级、同一桩小事上打转。
- 若发现连写十几章主角还停在原地（同一据点、同一职权、同一对手、同一类琐事），这是**节奏事故**，必须立刻提速：跳过过程、收束当前阶段、把舞台推大。
- **量级换挡是硬指标**：主角能调动的钱数／人手／地盘／对手层级，**每 10 章至少上一个台阶**（一个数量级，或至少数倍）。经商、种田、宗门、官场类尤其要紧——读者要**看见数字往上走**。若连写十几章主角的钱还在同一个位数上打转（始终几百块、始终一个铺子），这是节奏事故。
- **前世／未来的数目不算兑现**：重生类拿"上辈子我做过的最小一单是三十七万"作对照可以，那是钩子不是战果。读者要的是**本世账上的数字变大**。

**3. 爽点 / 阶段性胜利节拍**
- **每 5 章至少一次可感的兑现**：打脸一次／对手服软／收服一个人／揭开一层真相／上一个台阶／扳回一城。
- 可以压抑、可以隐忍，但不能**全程压抑没有兑现**；铺垫是为了爆发，长期只铺不发=劝退。
- **不许全员好人**：如果连着十几章里每个挡路的人最后都通情达理、主动让步、替主角着想（讲规矩的甲方、主动退让价的厂长、偷偷帮忙的老师傅、被一句话说服的对头），读者就失去了追读的理由。**任何时候至少留一个真正的对手**：他有自己的算盘、不肯让、且**赢过主角一回**。
- **主角别总是主动让利**：克制、退让、只答应一半能立人物，但每让一次就是把读者的快感让出去一次——让了就要在别处兑现回来。
- **信息优势必须兑现**：穿越／重生／金手指类，主角的核心优势要**真正用出来并产生别人做不到的结果**。若连写十几章，主角做的每件事都是"任何一个本时代的聪明人也想得到的"，那个金手指等于不存在——而它正是读者点进来的理由。

**4. 写实 ≠ 流水账**
- 克制、细节、考据都为**人物与冲突**服务。当物件/流程/账目细节开始淹没情节推进时，**砍细节、保推进**。
- 宁可一句话概述三天的盘点，也不要用三章去写盘点。
- 办手续、对账、比价、验收、开单、跑批文这类事务，**连续 ≥2 章当主线会被节奏闸判为事故并退回重改**。它们只能是那场戏的赌注，不是那场戏本身。

**5. 上面这些不是建议——每批写完有代码在量**

写完一批后，【节奏闸】会自动量四样并把结论写进 `reviews/节奏体检-*.md`：**单章字数**、**事务流程密度**（章名 + 正文关键词）、**金额/规模曲线**（自动剔除前世回忆里的数目）、**章末钩子类型**（是具体事件/台词，还是总结抒情预告）。判为事故的批次会被**直接退回、要求就地改完才准写下一批**。所以别写完指望"下一批再补爽点"——那一批已经过不了闸。

**6. 体系性约束优先于单卷设定**
- 若 `novel_bible.md` 里的某条“口吻基线/限制/铁律”正在逼出流水账（例如要求“一切扩权都要逐一办牌验册、不许顺滑”），它**服从本节的节奏与格局要求**：合法性/写实可以用“几章一个里程碑”的方式表达，而不是“一章一张牌”。必要时在自检里提出并调整 bible 的该条规则。

## 场景与张力（把每章写成"有戏"的场景，不是流水叙述——好书与烂番茄的分水岭）

平庸的网文是"交代 + 赶路 + 报流水账"；好书的每一章都是一个**有张力的场景**。硬约束：

- **每章至少一个核心场景**，且这个场景要有完整的张力弧：主角有一个【当下明确的目标】→ 遇到【实打实的阻力】(对手、难处、两难、时限) → 中途有【转折】(意外/反转/底牌/代价浮现) → 结尾主角为推进【付出代价】或【拿到但埋下新麻烦】。别写"顺顺当当把事办了"。
- **用冲突驱动，不用信息驱动**：一章的主线不该是"交代一段设定/回顾/赶路"，而该是"人物这一刻**想要什么、被什么挡、怎么破、付出了什么**"。设定与背景只在冲突里带出来。
- **爽点是"担心后的兑现"，不是白给**：先让读者替主角捏把汗（代价、风险、被压制），再兑现（打脸/翻盘/上台阶）。无铺垫无代价的"爽"是塑料爽，读者不买账。
- **对话要推进，不要复述**：对话是交锋、试探、藏话、下套，用来推进关系与情节；禁止角色互相复述读者已知的信息。
- **每个重要配角要有"自己的欲望"**：反派/配角不是主角的背景板，他们各有想要的东西、各有算盘，冲突才立体。
- 写完一章自问：**这一章如果抽掉，故事塌不塌？** 塌，说明它有戏；不塌（只是过渡/交代），就重写成一个有目标-阻力-转折-代价的场景，或并进相邻章。

## 开篇定位（前 1–3 章，最高优先级）

网文开篇要让读者【迅速入戏、立刻知道自己在看什么】。前 1–3 章必须快速立住这四样，缺一会让读者看着发懵、弃书：

- **当下身份**：主角现在【是谁】——书名/卖点承诺的那个身份要尽早成为主角的"现在"。穿越/重生类：**尽快让主角"成为"新身份并展现新身份的看点**；前世只作惊鸿一瞥的钩子或一双"外挂的眼"，旧身份的死亡/回忆**控制在开篇一小段内**，绝不能长时间停在前世场景、不能让旧身份喧宾夺主（读者点的是新书名，要尽快见到那个人）。
- **时代与地点**：让读者【有画面地】知道何时、何地、什么世道——用合时代的实锚（器物、称谓、街景、时局、物价）落地，不是只甩一个年份。读者要能"看见"这个世界。
- **核心题材钩子与爽点承诺**：这本书的主菜（书名/卖点承诺的核心看点）要在开篇就让读者【尝到一口】，并埋下"还有更大的"的期待。
- **主要矛盾的影子**：让读者隐约看到主角要面对的大势/对手/目标，知道这本书"要往哪走"。

## 题材承诺兑现（贯穿全书，开篇尤重）

- 书名与一句话卖点承诺的【核心爽点/题材】，是读者点进来的理由，必须【尽早且持续兑现】。
- **严禁开篇长期只写支线题材而迟迟不上主菜**：例如一本主打"国术/武侠"的书，开篇几十章只写探案/日常/种田，会把冲着主菜来的读者赶走。支线可以有，但要与主菜并行、且让主菜先亮相、先尝到甜头。
- **多题材融合时（如"国术+神探""种田+争霸"），开篇就要让各条线都露脸**，不能一条独大几十章把另一条晾着——读者是冲着书名承诺的那个组合来的。

## 文风与反 AI 味（最高优先级，逐章自检）

本书文风的**唯一依据是 `style_refs/` 里的范本原文**。动笔前读一遍，写成那个样子。
下面只有三条与文风无关、任何书都成立的硬要求：

- **不要复读凑字**：不重复段落、不重复句式、不原地绕圈。写不动就自然收束。
- **不要放大自己的排版怪癖**：参考最近几章时【只学语气基线】，绝不复制或放大前文的排版 tic
  （满屏「……」、每句都单独成行）。**排版密度以 `style_refs/` 的范本为准**，不向最近几章的走样看齐——
  否则一批比一批夸张，滚成雪球。
- **不要作者旁白**：不解释自己在写什么、不总结、不点评、不写"欲知后事"。

> 关于句子该多长、段落该多厚、能不能用成语套话、要不要留白、细节该多密、章节怎么开头——
> **一概以范本为准，本文件不做任何规定**。


## 批次续写流程

1. 读上下文（bible / 当前卷大纲 / index 末尾 / 最近 3–5 章 / 最近自检）。
2. 选下一批章号与章名——每个章名都先在 `chapter_index.md` 全表查重，确保全书唯一、不与任何已有章名重复。
3. 创建每个章节 .txt 到正确卷目录。
4. 文件创建完成后，再在 `chapter_index.md` 写入对应行并标 `已写`。
5. 跑自检（文件存在 / .txt / 命名 / 章名唯一 / 卷目录 / 仅正文 / 字数达标 / index 一致 / 连续性 / 人物一致）。
6. 任何不达标的章节就地扩写（保留剧情框架与结局，只加细节）。
7. 生成 `reviews/起始-结束内容自检.md`。
8. 简要汇报：写了哪些章、改了哪些文件、自检结论、下一续写点。

## 自检（每批后）

- 全部目标章节文件存在且为 .txt；命名 = 全局章号 + 章名；章名全书唯一；在正确卷目录。
- 章节仅正文，无标题/注释/元信息。
- 每章 > 4KB 且正文 > 3000 字。
- `chapter_index.md` 行与路径一致。
- 剧情符合当前大纲（或明确记录一次合理的大纲更新）。
- 与上一批连续性完好；人物行为符合既定弧光；无重大线索/证人/物件/关系/伤势矛盾。

**内容质量·七维复核（每批扫一遍，发现问题就地精修那一处、不整章重写；把结论写进 reviews/）**：
1. **设定与专有名词一致**：世界观/规则/人物档案/原著武器与法宝（如萧炎必须用玄重尺、严防AI造词或错译）有没有对不上？——发现即引用原文举证并就地改。
2. **人物行为**：性格/动机/弧光是否站得住？有没有为了推进而 OOC？
3. **节奏格局**：这几章处境有没有可感升级？有没有卡在同一地点/同一桩小事打转？
4. **叙事连贯**：因果链、时间线、前后呼应有无断裂？
5. **伏笔**：本批埋了/推了/收了哪些？对照主线伏笔表，别埋了不收、也别凭空冒设定。
6. **章末钩子**：每章结尾有没有让人想看下一章的悬念/反转/新麻烦？
7. **文风**：把本章和 `style_refs/` 里的范本并排读一遍——**语感对不对味**？叙述者的姿态、句子的呼吸、段落的换行密度、用词口味、情绪的外放程度，是不是同一个人写的？不对味就往范本那边调。（不要去数长短句比例、不要扫套句黑名单——那是另一种审美，本书以范本为准。）

## 自动续写约定（Novel Studio 编排）

- 本项目由 Novel Studio 半自动驱动：你在可见的 Unterm 窗口里写作，编排器会监控你的进度。
- 当你完成一批并空闲时，编排器可能自动发来"继续"指令——请直接按规范续写下一批 3 章并自检。
- 当你需要在多个方案间抉择时，请显式给出"推荐项"（标注"推荐"），以便自动流程采纳。
- 默认输出落在 .txt 文件；除非用户要求，不要在对话里粘贴整章正文。

## 全文逻辑自检（周期性，区别于单批自检）

- 单批自检只覆盖最近一批；**全书的时间线、伏笔、人设、设定规则会随章数累积漂移**，必须周期性做全局核查。
- Novel Studio 每写够若干批会自动发来【全文逻辑自检】指令。收到后，不要只看最近一批，而要做全书级核查：
  时间线先后、人物弧光与性格一致性、力量/设定体系是否自洽、伏笔的铺设与回收、未决线索与"待查"项、
  事实/关系/伤势/物件/欠债的前后矛盾、章名与命名一致性、与各卷大纲的偏离。
- 把发现按【硬伤 / 隐患 / 待办】三档写入 `reviews/全文逻辑自检-至<最新全局章号>.md`；硬伤级矛盾就地修正
  （保持已写剧情框架与结局，只改必要处），无法当场修的明确记录为待办。
- **维护 `continuity_ledger.md`（连贯性台账）——分两区，两区的规矩完全相反**：
  文件顶部是「📌 当前态快照」段（到 `LEDGER_HISTORY_BELOW` 标记行为止），标记行以下是历史增量区。
  **写作时程序只把快照段喂进上下文，历史区一个字都不喂。** 所以：

  1. **快照段 —— 每批写完必须【就地改写】，有硬上限**。它代表【此刻】的状态，不是流水账：
     · 「`- 进度：已写到第 NNN 章`」这一行【格式不能改】，程序要读它校验快照有没有过期；
     · 人物现状：一人一行，处境变了就【就地覆盖】，绝不在同一个人下面追加历史流水；
     · 未回收伏笔 / 待查、欠债与承诺：**回收了就把那条删掉**，不要留「已于 XX 章兑现」的尸体；
     · 伤势 / 状态 / 关键物件去向、时间线锚点：同样只留当前态，变了就覆盖。
     **硬上限 3000 字符**——这一段每批都会被整段喂进上下文，写成流水账等于没压缩。
  2. **历史区 —— 只追加，不修改，且【不必压缩】**：本批新增的时间线、伏笔布点、来龙去脉
     追加到标记行以下。它不进写作上下文，所以不设长度上限，留着供全文自检与事后追溯。
     只有一种情况要动它：推倒重写某段剧情时，把对应的分章条目一并删掉——不要只加一句
     「以下不作数」就留着（这个坑真踩过：76,823 字符的废稿条目占了整份台账的 75%）。

  ⚠️ **快照过期 = 后面每一章都在照着旧状态写。** 这不是提醒，是程序会查的事：写完一批后
  有一道写后闸比对快照里的进度章号与实际最高章号，对不上就把你退回来重填快照、不许写新章。
